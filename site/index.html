A 12-DOF biped
you can print.

K2 is an open-source, 3D-printed bipedal robot built on twelve Feetech STS3215 serial-bus servos. A reinforcement-learning policy holds, marches, walks forward and backward, turns, and steps laterally. The same policy has been tested on the physical robot from a Raspberry Pi 5 and from a Seeed XIAO ESP32S3 running the network onboard.

  • 12 degrees of freedom
  • ≈0.45 m tall
  • ~$224 parts subtotal
  • 50 observations → 12 actions

Capabilities

What the shipped policy actually does.

Hold tested

Learned standing hold. Releasing every control requests hold rather than latching the last motion.

March tested

Stepping in place at the policy's gait frequency, the entry point to every travelling gait.

Walk tested

Forward and backward, trained to ±0.05 m/s. Backward is a sign flip of the forward task.

Turn tested

Yaw on top of forward/backward travel, trained to ±0.30 rad/s.

Lateral tested

Side-stepping, trained to ±0.03 m/s, with leading-foot selection in the command profile.

Height & planted rotation not shipped

Body-height control and feet-planted rotation are not part of the released policy.

Acceleration is deliberate. Both the web and joystick paths keep the trained acceleration and jerk limits, so reaching maximum speed is gradual. Commands expire after 500 ms without a refresh, which requests a smooth stop rather than freezing the last command.

Interactive model

See which servo moves which joint.

The joint viewer loads K2's model in the browser and gives you a slider for each of the twelve joints. Every slider is labelled with the servo ID on the bus, its operational limit, and a plain-language description of what a positive command does to that leg.

The geometry is baked straight out of mjcf/k2_physics.xml — the model the policy actually trains on — and the limits from hardware/joint_limits.json, the ranges the robot actually runs. The browser's kinematics are checked against MuJoCo's own forward kinematics at build time, so what you drag is what the robot does.

PeripheralXIAO pin

LSM6DS3 SCLD5 / GPIO6
Servo driver RXD6 / GPIO43 (ESP TX)
Servo driver TXD7 / GPIO44 (ESP RX)

Share ground. The Waveshare driver must be set to TTL, not USB. The servo UART runs at 1 Mbps. Full procedure in the ESP32-S3 README.

Software

Drive the digital twin without owning a robot.

The same controller code drives MuJoCo or the real servo chain — --bus is the only thing that changes. On a Linux desktop with a graphical session, no GPU training stack or physical hardware is needed:

git clone https://github.com/kapalikkhanal/K2.git && cd K2
python -m venv .venv && source .venv/bin/activate
pip install -r hardware/requirements-pi.txt

python keyboard.py --policy policies/last_policy.onnx

Focus the MuJoCo viewer to use the keys. --policy takes an ONNX file, not a training .pt checkpoint; omitting it selects the shipped policy.

Status

What is proven, and what is not.

Demonstrated

Maintainer-tested physical operation on both controllers, with the shipped policy, on the original robot. Launcher regression tests pass, and the ESP32 build is verified against the Python implementation on the host.

Not established

Rough-terrain reliability, endurance, and performance across independently built robots are not quantified. Host verification is not a physical test, and one robot is not a sample.

Safety. The ESP32 web interface runs an access point with a documented default password and unauthenticated local control endpoints. Use it on a trusted local network, change the password for public demonstrations, and never expose it to the internet. Support the robot before enabling torque.
